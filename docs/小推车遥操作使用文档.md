## X5 接收端

**X5 板 SSH 地址：**有线连接使用 `192.168.25.1`；无线连接使用 `172.100.10.159`。下方命令默认使用无线地址，若走有线连接，请将命令中的 `172.100.10.159` 替换为 `192.168.25.1`。

### 部署软件包

```bash
# 1. 将 X5 接收端 deb 包复制到目标设备的 /tmp 目录
scp \
  arm_app_0.3.9-alpha1_20260713165025_arm64.deb \
  wcr_rc_app_1.0.0_20260714025908_arm64.deb \
  robot_app_1.3.1-17-gc035b572a_20260708191104_arm64.deb \
  root@172.100.10.159:/tmp/

# 将一键启动脚本复制到 X5 的 /root 目录
scp start_x5_arm_remote.sh root@172.100.10.159:/root/

# 2. 在目标设备上安装三个 deb 包
ssh root@172.100.10.159 \
  "dpkg -i \
  /tmp/arm_app_0.3.9-alpha1_20260713165025_arm64.deb \
  /tmp/wcr_rc_app_1.0.0_20260714025908_arm64.deb \
  /tmp/robot_app_1.3.1-17-gc035b572a_20260708191104_arm64.deb"

# 3. 确认安装版本、架构和安装目录，并给启动脚本添加执行权限
ssh root@172.100.10.159 \
  "dpkg-query -W -f='\${Package}\t\${Version}\t\${Architecture}\n' arm_app wcr_rc_app robot_app && \
  ls -ld /opt/arm_app /opt/wcr_rc_app /opt/robot_app && \
  chmod +x /root/start_x5_arm_remote.sh"
```

# 软件使用

**启动顺序：**请先在 X5 板启动接收端：`cd /root && ./start_x5_arm_remote.sh`。确认 X5 接收端正常运行后，再启动 PC 端 `data_collector`；否则 PC 发送端无法正常建立连接。

## PC 发送端

### 启动

```bash
# 可从 Ubuntu 应用菜单打开“轮椅控制端”，也可在终端启动
data_collector
```

如果点击**开启臂服务**后启动失败，可先重启 `data_collector` 软件后重试；如仍无法启动，可插拔两侧一代臂 CAN 口后再次尝试。

### 界面操作

启动后按以下顺序操作：

1. 点击界面左侧的 **双臂**，切换到双臂遥操作界面。

2. 点击界面下方的 **开启臂服务**，启动 PC 端左右一代臂服务；两侧一代臂会自动运动到遥操位姿。

3. 等待臂服务启动完成后，点击界面下方的 **遥操模式**，进入双臂遥操作模式。

**安全注意：**开启或停止臂服务时，机械臂会自动运动。操作前请确认机械臂运动范围内无人员和障碍物，并与机械臂保持安全距离。

### CAN 速率异常处理

**注：一键启动脚本会自动配置左臂 ****`can1`**** 和右臂 ****`can0`****。如仍遇到被控二代臂服务超时，使用以下命令重新设置 CAN 速率。**

```shell
# left 为 can1，right 为 can0
ip link set can1 down
ip link set can1 type can bitrate 1000000 dbitrate 5000000 fd on restart-ms 100 berr-reporting on
ip link set can1 up
ip -details link show can1
```

### AIRRTM 配置说明

**新版 ****`wcr_rc_app`**** 可通过 ****`/opt/wcr_rc_app/configs/remote_airrtm_config.json`**** 修改 AIRRTM 配置：**

注：建议为每台设备单独配置 `room_id`、`user_id` 和 `user_name`，避免与其他设备重复或串连。

```json
{
  "defaults": {
    "server_url": "https://8.138.229.216:7210",
    "user_id": "xf6600_cart_air_airrtm",
    "user_name": "xf6600_cart_air_airrtm",
    "token": "",
    "room_id": "xf6600_cart_air",
    "connect_mode": "signaling",
    "direct_role": "controlled",
    "ws_url": "",
    "ws_server_port": 0,
    "data_channel_label": "airrtm_control",
    "reliable": false,
    "ordered": true
  },
  "instances": {
    "operator": {
      "user_id": "xf6600_cart_air_airrtm_operator",
      "user_name": "xf6600_cart_air_airrtm_operator"
    }
  }
}
```

注：若网络较差，可使用 direct 模式，按如下修改：

```json
# 接收端：/opt/wcr_rc_app/configs/remote_airrtm_config.json
"connect_mode": "direct",
"direct_role": "controlled",
"ws_server_port": 9000
```

```yaml
# PC 发送端 data_collector
connect_mode: "direct"
ws_url: "ws://192.168.25.1:9000"
```

各个字段含义：

|配置段|字段|含义|常用修改|
|---|---|---|---|
|`defaults`|`server_url`|AIRRTC 信令服务器地址|切换测试、生产或内网服务器|
|`defaults`|`user_id`|X5 端用户 ID，需和对端区分|多机器人接入时改成唯一 ID|
|`defaults`|`user_name`|X5 端用户名|通常和 `user_id` 保持一致|
|`defaults`|`token`|加房鉴权 token，空表示不用 token|服务器开启鉴权时填写|
|`defaults`|`room_id`|AIRRTC 房间 ID|切换遥操房间，PC 与 X5 必须一致|
|`defaults`|`connect_mode`|连接模式：`signaling` 或 `direct`|常规使用 `signaling`，直连调试使用 `direct`|
|`defaults`|`direct_role`|直连角色：`controller` 或 `controlled`|X5 端使用 `controlled`|
|`defaults`|`ws_url`|WebSocket 地址|X5 作为受控端时通常留空|
|`defaults`|`ws_server_port`|WebSocket 服务端口|直连模式可设置为 `9000`|
|`defaults`|`data_channel_label`|DataChannel 标签|必须和 PC 发送端一致|
|`defaults`|`reliable`|是否可靠传输|默认 `false`，需要重传时改为 `true`|
|`defaults`|`ordered`|是否按顺序交付|默认 `true`|
|`instances.operator`|`user_id`|operator 实例用户 ID|多设备时改成唯一 ID|

# 遥操作效果

### 具体测试情况及结论

1. \*\*测试自研 RTM 链路：\*\*在无线 局域网情况下，最大峰值延迟有 **150ms**，导致机械臂遥操作出现抖动卡顿情况，目前效果不能达到要求；目前优先级 P0，预计时间 2\-3 周时间

2. \*\*测试自研 RTC 图传链路：\*\*在无线局域网情况下有 **200\-300 多 ms **延迟，目前也无法满足使用要求（must 130ms 内，nice to have 90ms）；目前优先级 P1，预计时间 2\-3 周时间

# 数采接口

本文针对 `configs/projects/HY6310_airrtm_control` 当前配置，整理数据采集需要关注的最小 topic 集合，并说明 FSM 下发给 `arm_control` 的 action、`arm_control` 反馈 state 和 H264 图像数据的消息格式示例。

## 最小采集数据

|action|左臂 arm \+ 夹爪|`rt/arm/left/control/control_command`|`arm_msgs::msg::dds_::ControlCommand_`|FSM 最终下发给左臂 `arm_control` 的控制命令；arm 和夹爪通过 `joint_names` 区分|

## 机械臂关节 Action

本文档的 action 只记录 FSM 周期性发布到 `arm_control` 的 `control_command`，这是实际进入 `arm_control` 的主控制命令，适合作为训练数据中的 action 对齐源。

最小建议采集以下 action：

|手臂|topic|类型|说明|
|---|---|---|---|
|左臂 arm \+ 夹爪|`rt/arm/left/control/control_command`|`arm_msgs::msg::dds_::ControlCommand_`|FSM 下发给左臂 `arm_control` 的主控制命令；夹爪也复用这个 topic|
|右臂 arm \+ 夹爪|`rt/arm/right/control/control_command`|`arm_msgs::msg::dds_::ControlCommand_`|FSM 下发给右臂 `arm_control` 的主控制命令；夹爪也复用这个 topic|

### Action 消息格式

`arm_msgs::msg::ControlCommand` 定义在 `framework/dds/msg/arm_msgs/msg/ArmControl.idl` 中：

|字段|类型|说明|
|---|---|---|
|`header`|`std_msgs::msg::Header`|时间戳和 frame 信息|
|`joint_names`|`sequence<string>`|本条命令包含的关节名，顺序与 `commands` 一一对应|
|`commands`|`sequence<JointCommand>`|每个关节的控制目标|

`JointCommand` 的字段如下：

|字段|类型|单位|说明|
|---|---|---|---|
|`position`|`double`|arm: rad; G2P: m|目标关节位置或夹爪行程|
|`velocity`|`double`|arm: rad/s; G2P: m/s|目标关节速度或速度上限|
|`kp`|`double`|\\\-|MIT/力控模式下的位置增益|
|`kd`|`double`|\\\-|MIT/力控模式下的速度增益|
|`torque_ff`|`double`|Nm|前馈力矩|
|`max_torque`|`double`|Nm|最大力矩限制|

## 机械臂模式

机械臂模式建议分两层采集：

- 高层控制状态：看 FSM 发布的 `rt/arm/<left|right>/fsm/state`，用于区分当前是 `SERVO_CONTROL`、`PLANNING_CONTROL`、`POSITION_CONTROL`、`FORCE_CONTROL` 等。

- 底层控制器模式：看 `arm_control` 发布的 `rt/arm/<left|right>/control/controller_state`，用于记录 arm/eef 当前实际控制器模式， 例如 `csp`、`mit`、`trajectory`。

|数据|左臂 topic|右臂 topic|类型|说明|
|---|---|---|---|---|
|FSM 高层状态|`rt/arm/left/fsm/state`|`rt/arm/right/fsm/state`|`arm_msgs::msg::dds_::FsmState_`|判断样本处于 servo、planning、position、force 等哪类控制状态|
|arm\\\_control 底层模式|`rt/arm/left/control/controller_state`|`rt/arm/right/control/controller_state`|`arm_msgs::msg::dds_::ControllerState_`|记录 arm/eef 底层控制器当前模式和 manager 状态|

### FSM State 消息格式

`arm_msgs::msg::FsmState` 定义在 `framework/dds/msg/arm_msgs/msg/FiniteStateMachine.idl` 中：

|字段|类型|说明|
|---|---|---|
|`header`|`std_msgs::msg::Header`|时间戳和 frame 信息|
|`state`|`uint8`|FSM 高层状态值；负数状态需要按 `int8` 解释|
|`active_request_id`|`string`|当前正在执行的请求 ID；空字符串表示当前无活跃请求|
|`last_error`|`string`|最近一次错误信息；空字符串表示无错误|

`state` 的含义如下：

|数值|状态名|说明|
|---|---|---|
|`-3`|`UNKNOWN_ERROR`|未知错误|
|`-2`|`IN_COLLISION`|碰撞保护状态|
|`-1`|`EMERGENCY_STOPPED`|急停状态|
|`0`|`IDLE`|空闲|
|`1`|`PLANNING_CONTROL`|规划控制模式|
|`2`|`GRAVITY_COMPENSATION`|重力补偿模式|
|`3`|`SERVO_CONTROL`|Servo 控制模式|
|`4`|`POSITION_CONTROL`|位置控制模式|
|`5`|`FORCE_CONTROL`|力控模式|

示例：

```JSON
{
  "header": {
    "stamp": {
      "sec": 1710000000,
      "nanosec": 126000000
    },
    "frame_id": ""
  },
  "state": 3,
  "active_request_id": "servo_left_001",
  "last_error": ""
}
```
